# Live-host recording script: VM/370 R6 (TK4-/TK5 companion CMS image) under
# Hercules.
#
# STATUS: not yet run against a live host. This is the starting point from
# the stage-1 plan (Task 16), not a verified transcript. See
# docs/live-testing.md for the runbook this script is part of.
#
# Usage:
#   node packages/cli/dist/main.js < packages/cli/scripts/record-vm.txt \
#     > /tmp/vm-session.log 2>&1
#
# Before running, substitute the real HOST:PORT for the Hercules instance's
# 3270 listener in the Connect() line below. This is very likely a different
# port than the MVS listener even on the same Hercules host, since each
# guest OS typically gets its own configured device/port — check the
# instance, do not assume it matches record-mvs.txt.
#
# The username below (CMSUSER) is a placeholder, not a real TK4-/TK5 default:
# unlike MVS's HERC01/CUL8TR pair, VM/370 turnkey builds vary in which CMS
# userids are provisioned out of the box. Read the CP logon screen produced
# by the first ScreenText and substitute a userid (and password, if the
# build requires one at LOGON rather than only at further CP commands) that
# actually exists on the target system.
#
# As with record-mvs.txt: the operator MUST read the ScreenText output at
# each step rather than trust the "ok"/"error" status lines alone. CP will
# happily accept a garbled LOGON line and print an error panel that still
# produces a normal-looking "ok" status from this CLI; only a human reading
# the panel text distinguishes a real CMS ready prompt from a rejected logon.

Trace(on)
Connect(HOST:PORT)
Wait(3270Mode,30)
ScreenText
String("LOGON CMSUSER")
Enter
Wait(Output,30)
ScreenText
Enter
Wait(Output,30)
ScreenText
String("QUERY TERMINAL")
Enter
Wait(Output,30)
ScreenText
String("LOGOFF")
Enter
Wait(Output,10)
Trace(off)
Quit
